# Issue 23 작업 로그

## 주요 결정사항

- 카테고리별 "전체" 선택은 API에서 `topics: []`로 표현한다.
- `CsSubjectRequest.topics`의 `@Size(min = 1)` 검증을 제거해 빈 배열을 허용했다.
- 빈 토픽 카테고리가 저장 과정에서 사라지지 않도록 `InterviewCsSubjectEntity`에는 내부 마커를 저장하고, `InterviewFinder` 조회 시 다시 빈 배열로 복원한다.
- 질문 생성 프롬프트에서는 빈 토픽을 `{카테고리명} 전체 범위에서 랜덤` 문구로 변환한다.
- 프론트엔드는 카테고리별로 `전체/개별주제/직접입력` 중 하나만 선택되도록 상호 배타적으로 처리한다.

## 포기한 접근법

- 문자열 `"전체"`를 토픽으로 저장하는 방식은 실제 사용자 직접 입력값과 충돌할 수 있어 사용하지 않았다.
- 전체 선택 시 예시 토픽 전체 배열을 보내는 방식은 "예시 주제 외 전 범위"라는 요구를 정확히 표현하지 못해 사용하지 않았다.
- 빈 배열을 그대로 저장하지 않는 기존 저장 로직은 조회/질문 생성 단계에서 선택 카테고리 정보가 소실되어 보완했다.

## 다음 작업 참고

- `topics: []`는 공개 API 계약이며, `docs/api.md`에 반영되어 있다.
- 내부 마커 값은 DB 저장용 구현 세부사항이므로 응답이나 프롬프트로 노출되면 안 된다.
- 직접 입력은 쉼표로 여러 주제를 구분한다. 쉼표를 포함한 단일 주제명이 필요한 UX는 별도 입력 방식 검토가 필요하다.
- #23은 기존 미병합 브랜치(`feature/issue-23-backend`, `feature/issue-23-frontend`)가 있었지만 오래되어 현재 `main` 기준 `*-rework` 브랜치에서 재구현했다.
