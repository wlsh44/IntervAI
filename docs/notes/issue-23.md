# Issue 23 작업 로그

## 주요 결정사항

- 카테고리별 "전체" 선택은 API에서 `topics: ["ALL"]`로 표현한다.
- `ALL` 토픽은 저장/조회에서는 그대로 유지하고, 질문 생성 프롬프트에서 `{카테고리명} 전체 범위에서 랜덤` 문구로 변환한다.
- 프론트엔드는 카테고리별로 `전체/개별주제/직접입력` 중 하나만 선택되도록 상호 배타적으로 처리한다.

## 포기한 접근법

- 문자열 `"전체"`를 토픽으로 저장하는 방식은 직접 입력값과 충돌할 수 있어 사용하지 않았다.
- `topics: []`를 전체 선택으로 표현하는 방식은 빈 배열 검증과 저장 의미가 모호해 `ALL` 명시 토큰으로 대체했다.
- 빈 배열을 카테고리 기본 토픽 목록으로 확장하는 방식은 "카테고리 전 범위에서 랜덤" 요구를 좁힐 수 있어 사용하지 않았다.

## 다음 작업 참고

- `topics: ["ALL"]`는 공개 API 계약이며, 백엔드 프롬프트 생성 시 카테고리 전체 범위 랜덤으로 해석된다.
- 직접 입력은 쉼표로 여러 주제를 구분한다. 쉼표를 포함한 단일 주제명이 필요한 UX는 별도 입력 방식 검토가 필요하다.
- #23은 기존 미병합 브랜치(`feature/issue-23-backend`, `feature/issue-23-frontend`)가 있었지만 오래되어 현재 `main` 기준 `*-rework` 브랜치에서 재구현했다.
