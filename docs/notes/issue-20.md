# Issue 20 작업 로그

## 주요 결정사항

- 면접 채팅 답변 제출 시 후보자 메시지를 먼저 추가하는 optimistic update 방식을 적용했다.
- LLM 응답 대기 중에는 면접관 말풍선 영역에 로딩 스피너를 표시하고, 다음 질문 수신 시 해당 스피너를 실제 면접관 메시지로 교체한다.
- 피드백 연결은 답변 내용 문자열이 아니라 optimistic message id 기준으로 처리했다. 같은 답변 문장을 반복 입력해도 올바른 메시지에 피드백을 붙이기 위함이다.

## 포기한 접근법

- API 응답 성공 후 후보자 메시지와 면접관 메시지를 동시에 추가하는 기존 방식은 제출 직후 사용자의 액션이 화면에 반영되지 않아 유지하지 않았다.
- 답변 content 기준으로 피드백을 연결하는 방식은 동일 문장 반복 입력 시 잘못된 메시지를 갱신할 수 있어 사용하지 않았다.

## 다음 작업 참고

- 답변 제출 실패 시 optimistic 후보자 메시지와 로딩 메시지를 제거하고 같은 질문에 다시 답변할 수 있도록 `pendingQuestionId`를 복구한다.
- 채팅 메시지 타입에 `isLoading` 플래그가 추가됐으므로, 이후 메시지 렌더링 로직을 확장할 때 로딩 메시지 처리 여부를 함께 확인해야 한다.
- 이번 작업은 프론트엔드 UI 상태 변경만 포함하며 API 계약 변경은 없다.
